## 5. Gotchas log (hard-won — do not relearn)

1. `Number("")` is `0` — blank price inputs once wiped the catalog. Reviews assert rendered **counts**, never status-only.
2. `gap-8` on `editorial-grid` collapses 1fr tracks at 320px (11×32px gutters > 288px container). The utility owns the gap — see `globals.css` comment.
3. `db.transaction` forbidden (neon-http). Atomic conditional UPDATEs + compensate instead.
4. Bare `.returning()` only (neon-http typings reject column args).
5. Empty-string env defeats `??` — use `||` for env fallbacks (`drizzle.config.ts` pattern).
6. `@better-auth/cli` npm tag is stale (1.4.x) — generate schema via `npx auth@latest generate`.
7. Incremental builds flake on stale `.next` (`pages-manifest.json ENOENT`) — `rm -rf .next` and rebuild.
8. `pkill -f` matches its own shell — kill Next servers by PID.
9. `Intl.NumberFormat("en", {currency:"NGN"})` renders the code — use per-code locales (`en-NG` → ₦) with symbol fallback.
10. Orchestration that works: implement agent → **separate** review agent → fix → verify (build + renders + counts + clicks). Structural checks alone ship toy-grade defects.
11. `"use server"` files cannot export non-async values (constants/helpers) — build fails "Server Actions must be async". Keep `BUYER_CANCEL_WINDOW_MS` / `isBuyerCancellable` in `lib/order-machine.ts`, import into actions + pages.
12. Client components cannot use `<a href="/…">` for internal nav (`no-html-link-for-pages`) — use `next/link` even for legal links in `CheckoutForm`.
13. Gotcha #5 hit AGAIN in Phase 1–4: `??` with empty-string env in `lib/contact.ts` (`SUPPORT_PHONE`, `APP_URL`/`NEXT_PUBLIC_APP_URL`) and `lib/email/notify.ts` (`ADMIN_EMAILS`, `MAILGUN_DOMAIN`) silently kept `""` instead of falling back. Fixed `??` → `||` in all four sites. Grep for `?? ""` on every env read.
14. Login `callbackURL` self-redirect loop: guard only checked leading `/`, so `/login?callbackURL=/login…` looped back instead of landing. `safeCallback` now rejects `/login`, `/login?…`, `/login/…`, `/login#…` → `/shop`.
15. Cart drawer decoupled from router stayed open over the new page. Drawer now closes on `pathname` change and every drawer link calls `onNavigate={close}`.
16. In-memory-only checkout form was wiped by Terms/Shipping/Returns/orders links. Draft now persists to `sessionStorage` (`checkout-draft-v1`, field allowlist + zone/currency validated against live lists) and restores client-only after hydration; cleared on successful order.
17. `loadCart` silently dropped hidden/deleted lines, so shoppers never learned why the bag shrank. Server now returns `removedCount/removedNames/removedIds` + `outOfStockCount`; UI shows a named banner (`slice(0,3)` + "and N more") with purge + undo.
18. Guest `write()` swallowed every storage exception, so full/blocked storage silently lost the bag. `write()` now throws coded `STORAGE_FULL` (`QuotaExceededError`/`NS_ERROR_DOM_QUOTA_REACHED`/`SecurityError`/code 22/1014) and callers surface the banner.
19. One-shot `?new=1` thank-you replayed on refresh/share. `StripNewParam` keeps the server `isNew` first render, then `router.replace` strips the param; idempotent re-orders redirect WITHOUT `?new=1`.
20. Generic "could not load" hid expired sessions. `UNAUTHENTICATED` now branches to a sign-in-again prompt (cart: link to `/login?callbackURL=%2Fcart`; checkout: `sessionExpired` flag) instead of the generic error.
21. Root layout always rendered shopper chrome, so `/admin` leaked header/footer/drawer. `SiteChrome` (client, `usePathname`) returns bare `{children}` on `/admin` — admin shell stays minimal with its own `AdminNav`.
22. Focus bugs ship silent: every modal (checkout confirm, drawer, cancel) needs initial focus + Tab trap + Escape + focus-return-to-opener, or keyboard users are stranded. Pattern mirrors `CancelOrderButton`; test with keyboard, not eyes.
23. `tsc --noEmit` in a stale-`.next` tree reports only TS6053 missing `.next/types/**` files (gotcha #7 family) — filter those before judging; zero non-`.next` errors = clean. Never "fix" by touching `.next`.
24. `ADMIN_EMAILS` is retired as an ACCESS gate but still live for MAIL routing (`notify.ts` admin digest, `contact.ts` `supportEmail()` fallback, `payments.ts` queued mails). Never grep-delete it wholesale; the gate removal lives in `auth-session.ts` (`getSessionProfile` always `customer`) + middleware split only.
25. `lib/paystack.ts` must stay client-safe (no node imports — Web Crypto HMAC) because the checkout confirm modal imports its kobo/inline constants. Server-only pieces (secret bearer verify/refund) live in actions + webhook route, never in that module's client-imported surface.
26. Paystack webhook needs the RAW body (`req.text()`) for the HMAC check — parsing JSON first destroys the signature basis. Non-200s make Paystack retry, so only signature/infra failures return 4xx/5xx; already-handled/benign events ack 200.
27. `finalizePaidOrder` (like COD `createOrder`) uses sequential statements + conditional UPDATEs — NEVER `db.transaction` (neon-http forbids it, gotcha #3). Webhook + verify can race: `queueOrderEmails` is `onConflictDoNothing` and same-ref `paid_online` returns success.
